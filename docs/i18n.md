# Internationalization (i18n)

PesoWise supports **English** (default), **Hindi**, and **Gujarati** for authenticated app routes and `/auth`.

## Stack

- [i18next](https://www.i18next.com/) + [react-i18next](https://react.i18next.com/)
- Locale files: `src/locales/{en,hi,gu}/*.json`
- Config: `src/i18n/`

## User preference

- Stored in `profiles.preferred_language` (`en` | `hi` | `gu`)
- Changed in **Settings → App language**
- Applied on login via `AuthContext` + `changeAppLanguage()`

## Adding strings

1. Add the key to `src/locales/en/<namespace>.json` (source of truth).
2. Add the same key to `src/locales/hi/` and `src/locales/gu/` with translations.
3. Run `npm run i18n:check` — fails if keys are missing in hi/gu.
4. Use in components:

```tsx
const { t } = useTranslation("expenses");
<Button>{t("submitExpense")}</Button>
```

## Namespaces

| Namespace | Usage |
|-----------|--------|
| `common` | Shared buttons, errors |
| `auth` | Sign-in page |
| `nav` | Sidebar, layout roles |
| `dashboard`, `expenses`, `admin`, … | Feature pages |
| `help` | Help & tutorial content |

## Help / tutorial content (`help` namespace)

**Source of truth:** `src/locales/en/help.json` (hand-maintained).

The Help page (`HelpTutorial`) loads content via `useTutorialManual`, which reads the `help` namespace and filters sections by organization feature flags.

### Feature-gated sections

Optional tutorial sections and quick links may include:

```json
"admin-module-4-hierarchy-teams": {
  "requiresFeatures": ["approval_hierarchy"],
  "title": "...",
  "paragraphs": ["..."]
}
```

- `requiresFeatures` — array of `organization_features.feature_key` values from `src/lib/organizationFeatureKeys.ts`.
- A section or quick link is shown only when **all** listed features are enabled for the current org (`hasOrganizationFeature` in `AuthContext`).
- Omit `requiresFeatures` for content that always applies.
- Do **not** translate `requiresFeatures` values or `route` paths; translate `title`, `paragraphs`, and `label` only.

### Roles

Manuals exist for: `admin`, `cashier`, `engineer`, `employee`, `team_leader`, `executive`. The page maps the signed-in user role to the matching manual.

### Legacy generator

`src/content/tutorialManuals.ts` is used only by `npm run i18n:help`. That script emits `title` and `paragraphs` only — it will **strip** `requiresFeatures` if run on the current `help.json`. Prefer editing locale files directly. After any generator run, re-add metadata and re-translate hi/gu.

### Translating help

1. Update `src/locales/en/help.json`.
2. Mirror structure in `hi/help.json` and `gu/help.json` with Hindi/Gujarati copy.
3. Run `npm run i18n:check`.

## Out of scope

- Marketing/legal routes (`/`, `/features`, …)
- User-generated DB content (category names, custom field labels, etc.)

## Failsafes

- `fallbackLng: 'en'` — missing keys show English
- DB constraint on `preferred_language`
- Invalid profile value normalized to `en` in app code
