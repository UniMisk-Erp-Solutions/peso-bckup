# End-to-end production runbook (PesoWise → TallyPrime)

For the live-refresh and Claim Verification blank-row investigation, see [LIVE-REPORT-REFRESH-AND-CLAIM-ROWS.md](./tally-integration/LIVE-REPORT-REFRESH-AND-CLAIM-ROWS.md). Five Claim Verification metadata ledgers were confirmed by read-only Tally Export on 12 October 2026; the updated TDL adds flat-row fallback and a 10-second refresh timer. The files are staged under `C:\pesowise`, but require one-time TDL reload before the running Tally process uses the change.

Single checklist from zero to Daily Project rows in Tally — no `npm run dev` on customer PCs.

## A. One-time (org admin — web)

1. Sign in as **admin** → **Tally integration** (`/admin/tally`).
2. Set **Tally company name** (exact match to TallyPrime company).
3. **Reports** → use **Sync to Tally** only after the Tally-side metadata setup below has been verified and explicitly attested.

## B. One-time (each Tally PC)

1. Build bundle (developers):

   ```powershell
   cd peso-bckup-priyanshu
   node scripts/tally-integration/build-customer-bundle.mjs
   ```

2. Copy `installer/out/` to the PC → run **Install-PesoWise-Tally.ps1** as Administrator.

3. TallyPrime:
   - Open the company saved in PesoWise.
   - **F12** → load `C:\pesowise\PesoWise-Bootstrap.tdl` and `PesoWise-Load.tdl` (not SafeMenu).
   - **F1 → TallyPrime Server** → enable HTTP **port 9000** for that company.

4. In PesoWise **Tally integration** → **Generate pairing code** → run the copied PowerShell command on that PC.

5. Connector runs at logon (hidden) or manually:

   ```powershell
   & "$env:ProgramFiles\PesoWise\TallyConnector\PesoWiseSync.exe" run
   ```

6. Confirm **Connector online** on the admin page.

7. In the isolated test company, confirm both `PesoWise-Bootstrap.tdl` and `PesoWise-Load.tdl` are loaded, the `PesoWise Reports` menu shows all four report entries, and the shared `PesoWise Metadata` ledger group exists. Review Tally's Import Exceptions report before starting a fresh test; never replay a batch in manual review.

8. Attest that setup from PowerShell only after the checks above:

   ```powershell
   & "$env:ProgramFiles\PesoWise\TallyConnector\PesoWiseSync.exe" confirm-metadata --company "PesoWise Integration Test" --confirm-installed --confirm-group
   ```

   The gate is scoped to the configured company and connector version. A company or connector-version change makes it unready again. Connector startup never claims queued or historical batches.

## C. Every sync

1. Admin → **Reports** → tab → **Sync to Tally**.
2. The browser verifies connector pairing, organization, active company and metadata readiness before job creation.
3. Server prepares that report's batches. The local bridge accepts only the explicit new job requested by the Sync action.
4. The connector checks the active company before claiming and immediately before posting XML to `:9000`; exceptions or ambiguous outcomes stop for manual review.
5. UI reports completion only after the server accepts a successful acknowledgment. Tally report rows and totals still require independent readback for acceptance.
